# ADR 0003 — Identity and access boundary
Status: provisional. Use an external OpenID Connect identity provider after selection and review. Do not build password storage or accept client-supplied role headers. The API uses an injected token verification adapter; the default has no verifier and denies all protected requests. The test verifier is a fixture, never a deployment option. A production adapter must verify signatures with trusted keys, issuer, audience, expiry, allowed algorithms, and revocation/session policy; roles must come from approved server-controlled mappings. Require MFA for privileged users, short-lived sessions, secure cookie or token handling, and audit before production. No provider, credentials or real users configured. The access probe performs no mutation.
