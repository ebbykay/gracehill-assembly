# Identity persistence and audit foundation
Identities use the verified issuer and subject pair; new accounts default to disabled. Roles are assigned server-side, not accepted from request headers. The query adapter is deliberately disconnected from the running API until a real driver, trusted token verification and restricted database credentials are configured. Audit events contain actor, request correlation, action, outcome and timestamp only; do not store tokens or pastoral content. The schema is not tamper-proof: production requires separate insert/read grants, retention policy, access review and backup. Runtime connection pooling, readiness, audit enforcement and OIDC integration remain outstanding. Never add actual identities to this public repository.
