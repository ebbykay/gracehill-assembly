# Operational services batch
Migration 0008 establishes ministry assignments, finance entries and monthly ceilings, media revisions, minimal care follow-ups and announcements. Protected APIs expose bounded lists and validated creation. Financial amounts are integer pesewas; only approved entries contribute to the monthly cash summary. Finance creators submit their own records and a distinct approver must approve or reject; approved records cannot be edited via API. This is a cash movement register, not double-entry accounting. Media and announcements have explicit review transitions; no actual publishing or sending. Care records deliberately exclude notes and member identifiers. Ministry assignments require an existing member and ministry. No deletion endpoints. Existing finance/pastoral roles receive provisional write permissions; new approver, ministry and communications roles require organisational review. Shared runtime grants are not row-level security. Operational UI, pagination, audit read access, budget vs actual integration, reversal workflow, accounting controls, privacy review and hosted deployment remain required. Never store actual data in public demo or temporary database. CI uses synthetic fixtures.
